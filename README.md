# re-handbook · 逆向工程与模块开发工具书

一本**能照着做、并且知道何时该停**的逆向工程与 Android 模块开发手册。不是教程合集，也不含任何具体样本的答案。

三条入口，按你的处境选一条：

| 你要做的事 | 打开 |
|---|---|
| 新机器从零装环境（人读或 AI 照着执行） | **[DEPLOY.md](DEPLOY.md)** |
| 查流程、判据、报告模板、冲突裁决 | **[BOOK.md](BOOK.md)**（约 1200 行，0–9 章） |
| 直接拿脚本干活 | **[skills/](skills/)**（一目录一技能，含 `SKILL.md` + `scripts/`） |
| 让 AI Agent 接手这个仓库 | **[AGENTS.md](AGENTS.md)**（读取契约与硬规则） |

tools/ 放仓库自身的运维脚本（当前只有 push-api.sh：当 github.com:443 的 git 协议不可达时，改用 api.github.com 上传）。

## 这个仓库解决什么问题

工具和命令你都能搜到。真正耗时的是这几件事，也正是本书的全部内容：

- **判型**：这是 APK 还是 ELF、有没有壳、逻辑在 Java 还是 native（[BOOK 2.1](BOOK.md)）
- **顺序**：什么条件下才允许上动态分析，什么时候静态就够（3.1 / 4.1）
- **边界**：能证明什么、不能证明什么；"没找到"和"不存在"不是一回事（3.6 / 7.3）
- **不返工**：`--deobf` 之后别去 hook、别盲 hook `JNI_OnLoad`、模块入口别放错位置（3.3 / 4.3 / 6.1）
- **可交付**：报告怎么写才经得起追问（7.1 / 7.2 / 7.5）

## 三条硬规则（贯穿全库）

1. **静态分析不等于观测到执行。** 只能写"存在对 X 的调用点"，不能写"会调用 X"。
2. **页用尽不等于源完整。** 覆盖不足时，"没匹配到"不等于"不存在"。
3. **样本只读。** 原包进 `samples/`，派生物进 `work/`，任何修改留回滚点。

## 使用约定

- 脚本一律 bash，Windows 请用 Git Bash / MSYS，路径写 `D:/x` 或 `/d/x`。
- 所有脚本都可以 `--help` 或直接看头部注释；不依赖交互输入。
- 脚本只做**采集与校验**，不替你做判断；判断在 BOOK.md 对应章节。
- 本仓库不内置任何破解结果、不承诺绕过任何目标。

## 来源与许可

内容由三处来源交叉整合：REA（rea-agents 6.9.0 的文档与技能）、一套 Android 逆向技能语料（其中 `Android动态分析` 标注 Apache-2.0）、以及 `vector-xposed-module-skill`。

- 逆向相关的冲突一律以 **REA** 为准，裁决记录在 [BOOK 9.5](BOOK.md)（C-01…C-12）。
- 语料中与主题无关的部分（LLM 破甲/越狱提示词、纯 Flutter 开发规范）未纳入正文，舍弃原因见 [BOOK 9.7](BOOK.md)。
- 各上游文件的完整许可条款以原项目为准（待补充：本仓库未逐一核对每个上游文件的许可声明）。
